## 0. 竞品结论（决定了我们做什么、不做什么）

| 项目 | 它做什么 | 我们的差异 |
|---|---|---|
| `aschokinatgmail/annotation-mcp`（FastMCP，8 工具，MIT，239 测试，三平台 CI） | 给坐标 → 画标注 + 条码/OCR 检测 | **方向相反**。它 README 明写「要手动框选请自备前端」 |
| `aamar-shahzad/mcp-screenshot-server` | 截图 + 标注，30+ 工具 | 同上，全靠 AI 传坐标 |
| `smythmyke/markitup-mcp-server` | AI 标注 + 营销图 | 不产坐标/模板资产 |
| `caliperhq/annomate-examples` | 研究 Claude 在**像素级**给判断 | 让 AI 自己看，不是让人来指 |

**空白点确认**：没有「人在图上框 → 服务端出坐标 + 模板」的 MCP。我们做这个。

**但不从零造**：架构上直接沿用 `switchbm/claude-redline`（MIT）验证过的模式——MCP stdio + 本地 HTTP UI 双轨、工具 async 阻塞、用户提交后唤醒。它踩过的客户端超时坑我们直接吸收（见 §7）。

## 1. 进程与并发模型

```
   MCP client (Claude Desktop / Cursor / WorkBuddy)
        │  stdio (JSON-RPC)          ← ⚠️ stdout 是协议通道，绝不能 print
        ▼
   ┌─────────────────────────────────────────────┐
   │  server.py  (FastMCP, 7 个工具)              │
   │      │                                       │
   │      ▼                                       │
   │  SessionManager                              │
   │   ├─ Session s1 ── threading.Event + rev     │
   │   │    └─ ThreadingHTTPServer @127.0.0.1:8777│
   │   ├─ Session s2 ── ...        :8778          │
   │   └─ ...                                     │
   └─────────────────────────────────────────────┘
                    ▲  HTTP (只绑 127.0.0.1)
                    │
            浏览器页面（无 CDN、单文件内联）
```

**要点**
- 每个 session **自带一个 HTTP server 线程**，端口从 8777 起自动 +1（最多试 20 次）。
- 工具调用与 HTTP 线程通过 `threading.Event` + `rev` 计数器通信，**不轮询文件夹**。
- 进程生命周期 = MCP client 的生命周期。client 断开 → 所有 session 的 server 关闭。
- 同一时刻允许多个 session 并存（用户在两个窗口标两张图）。

## 2. 工具签名（7 个）

### 2.1 `annotate_image` — 开会话

```python
annotate_image(
    source: str | list[str] | None = None,  # 本地路径 / base64 / data URL / "screen"
    name: str | None = None,                # 会话名；ASCII slug 后作文件名，默认 board_ui
    open_browser: bool = True,              # 自动打开默认浏览器
    resize_to: tuple[int, int] | None = None,  # 可选归一化，默认不缩放（见 §5-2）
) -> {
    "session": "s1",
    "url": "http://127.0.0.1:8777/?s=s1",
    "images": [{"id": "img1", "name": "a.png", "size": [1920, 1080]}],
    "hint": "在浏览器里框选后点「保存」，然后调用 annotate_wait(session='s1')",
}
```

- `source=None` 且装了 `[screen]` extra → 抓当前屏幕；没装 → **报错里直接给安装命令**
  （`pip install image-annotate-mcp[screen]`），不静默降级。
- 传 list → 一次开多图会话（见 2.7）。

### 2.2 `annotate_wait` — 阻塞等（核心）

```python
annotate_wait(
    session: str,
    timeout_s: float = 240,   # ⚠️ 必须 < 客户端 timeout，见 §7
    since_rev: int = 0,       # 只等「rev 大于这个值」的新保存
) -> {
    "status": "saved" | "pending" | "cancelled" | "unknown_session",
    "session": "s1",
    "rev": 2,
    "saved_at": "2026-11-15 16:40:11",
    "images": [ ... 见 §3 ... ],
    "elapsed_s": 37.2,
    "hint": "用户还没点保存，可以再调一次 annotate_wait 继续等"  # status=pending 时
}
```

**三条硬约定**
1. **超时返回 `status="pending"` 而不是抛异常** —— 抛异常在多数 client 里会渲染成红色故障，让人以为工具坏了。
2. **`hint` 必须是动作**（判据 29）：「再调一次 wait」而不是「用户未完成」。
3. **`rev` 单调递增**。用户补标后再保存 → rev+1 → agent 用 `since_rev` 取增量，不用重看全量。

### 2.3 `annotate_status` — 非阻塞查

```python
annotate_status(session: str) -> {
    "status": "pending" | "saved" | "cancelled",
    "rev": 2, "items_count": 5, "elapsed_s": 12.4,
}
```

### 2.4 `annotate_cancel`

```python
annotate_cancel(session: str) -> {"ok": True, "closed": True}
```
关闭 HTTP server，唤醒所有等待方（`status="cancelled"`）。

### 2.5 `annotate_list` / 2.6 `annotate_load`

```python
annotate_list(limit: int = 20) -> [{"name","saved_at","images":2,"items":7,"path"}]
annotate_load(name: str) -> <完整 v2 JSON，见 §3>
```
落盘目录默认 `~/.image-annotate-mcp/annotations/`（可用 `--data-dir` / 环境变量覆盖）。

### 2.7 `annotate_export`

```python
annotate_export(
    name: str,
    fmt: str = "png",        # "png" | "py" | "json" | "yaml"
    out_dir: str | None = None,
) -> {"files": [...], "constants": "BOARD_UI_SIZE = (1920, 1080)\n..."}
```

`fmt="py"` 产出（这是「输出即代码资产」的兑现）：

```python
# generated by image-annotate-mcp — 不要手改
BOARD_UI_SIZE = (1920, 1080)
BOARD_UI_JINGKUANG = (1614, 398)  # 点选
BOARD_UI_CHUZHAN = (1671, 713, 240, 70)  # 框选 x, y, w, h
BOARD_UI_TEMPLATES = {
    "chuzhan": "features/board_ui__img1__item2.png",
}
```

## 3. 数据模型 v2（多图）

```json
{
  "schema": 2,
  "name": "board_ui",
  "created_at": "2026-11-15 16:32:04",
  "saved_at":   "2026-11-15 16:40:11",
  "rev": 3,
  "images": [
    {
      "id": "img1",
      "name": "主界面",
      "source": "file:/path/a.png",
      "size": [1920, 1080],
      "items": [
        {"index": 1, "name": "晶矿", "type": "point", "point": [1614, 398], "note": ""},
        {"index": 2, "name": "出战按钮", "type": "box", "box": [1671, 713, 240, 70],
         "note": "", "template": "board_ui__img1__item2.png"}
      ]
    }
  ]
}
```

**v1 兼容**：`store.load()` 遇到没有 `schema` / 没有 `images` 的旧文件（原型的 `<name>.json`），
自动把顶层 `items` + `size` 包成单图会话再返回。**旧标注文件不迁移、不改写**（只读兼容）。

Markdown 摘要同步产出，每张图一节（agent 读这个更快）：

```markdown
## img1 · 主界面（1920×1080）
| # | 名称 | 类型 | 坐标 | 模板 |
|---|---|---|---|---|
| 1 | 晶矿 | 点选 | (1614, 398) | |
| 2 | 出战按钮 | 框选 | x 1671 y 713 240×70 | `board_ui__img1__item2.png` |
```

## 5. 原型里必须改的 6 处（都有行号）

| # | 问题 | 证据 | 改法 |
|---|---|---|---|
| 1 | **print 到 stdout** | `annotate.py:437,453,465` `print(...)` | MCP stdio 下 stdout 是协议通道，一 print 就破坏帧。**全部改 logging→stderr** |
| 2 | **强制归一化到 1920×1080** | `_grab()`/`_load()` 都过 `normalize()` | 任意图片不该被重采样。改 opt-in `resize_to`，且结果里同时报 `size_before/size_after`，否则坐标对不上原图 |
| 3 | **耦合 `hsr_mcp`** | `:56-57, 69-70` `from hsr_mcp import ...` | 解耦成独立包；抓屏走 extra |
| 4 | **「撤销」其实是删除** | `:285-288` `items.splice(...)` | 没有撤销栈，Ctrl+Z 删最后一项。改成真撤销/重做栈（栈里存整个 items 快照，简单可靠） |
| 5 | **框选中后不能移动/改大小** | 全文无 drag-handle 逻辑 | 加 8 个把手 + 整体拖移。这是标注工具的基本盘，缺了标错一个框就得重画 |
| 6 | **canvas 没处理 devicePixelRatio** | `:172-179` `cv.width = w`（CSS 像素） | 高分屏上框线糊、坐标偏 0.5px。backing store 用 `w*dpr`，绘制前 `ctx.scale(dpr,dpr)` |

**顺带更正一条继承来的结论**：原注释说「文件名必须 ASCII，因为 Windows 下 OpenCV 读写非 ASCII 路径会翻车」——
**那是 cv2 的缺陷，Pillow 支持 Unicode 路径**。但**建议保留 ASCII 文件名**，理由变了：
模板路径会写进 `py` 常量/配置被下游代码消费，ASCII 更安全。中文名照旧只放 JSON/Markdown。

其余原型的坑**原样继承**（坐标用 `naturalWidth/clientWidth`、端口递增、静音 log、保存前提示未改名、最小框选 6px、图片同源 base64）。

## 7. 风险（按严重度）

1. **客户端超时杀掉阻塞调用** —— `claude-redline` 实测：client 默认 60s，超时报
   `MCP error -32001: Request timed out`。对策：① 服务端默认 `timeout_s=240` 且**返回 pending 不抛异常**；
   ② README 里给出 `mcpServers` 配置片段，显式写 `"timeout": 600000`；③ 页面标题显示「等待中 / 已保存」。
2. **stdout 污染**（见 §5-1）—— 一旦 print，症状是 client 侧 JSON-RPC 解析失败，很难查。
3. **阻塞工具看起来像卡死** —— README 必须写清「这是 human-in-the-loop，agent 会阻塞等你操作」。
4. **`[screen]` extra 在 Linux 无头环境会挂** —— CI 里跳过该路径，README 注明。
5. **MCP Apps（SEP-1865）将来会取代「开浏览器标签页」** —— 前端做成独立 `web/index.html` 资源，
   将来可直接当 Resource 塞进 iframe，不用重写。

## 8. 我建议你重新考虑的一件事

你只勾了「多图会话」，**没勾「看图路径」**（用户只框不打字、agent 看带编号的图自己认名字）。

但你的原始动机是「我框一下，名字你认」——打字路径恰恰把这件事退化成「还得手打每个名字」。
成本上：带编号图**只是 `annotate_export(fmt="png")` 的另一个渲染分支**（框上写序号而不是名字），
约 30 行；而它省掉的是你每个元素都要打一次中文名。

建议 M1 里顺手加（不额外占里程碑），如果你坚持不要，我就按只做打字路径实现。
