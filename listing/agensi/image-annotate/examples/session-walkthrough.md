# Worked example

A full round trip, so you can see what the payloads actually look like before you run
one yourself.

## The situation

The user is building a click bot for a game. They paste a screenshot and say:

> 把这个「商店」按钮框出来，我要拿它做模板匹配

## 1. Open the session

```
annotate_image(source="C:/shots/hud.png", name="hud")
```

```json
{
  "ok": true,
  "session": "s1",
  "url": "http://127.0.0.1:8777/?s=s1",
  "name": "hud",
  "rev": 0,
  "images": [
    { "id": "img1", "name": "hud.png", "size": [1280, 720],
      "source": "C:/shots/hud.png" }
  ],
  "data_dir": "C:/Users/me/.image-annotate-mcp",
  "hint": "让用户在浏览器打开 ... 框选，然后点「保存」"
}
```

## 2. Tell the user what to do

> 页面已经打开了。请框出「商店」按钮，在右边把名字改成 `shop`，然后点保存。

Say what to name it. If you leave naming to chance you get `item1`, `item2`, and no one
knows which is which three sessions later.

## 3. Wait

```
annotate_wait(session="s1", timeout_s=240)
```

```json
{
  "schema": 2,
  "session": "s1",
  "name": "hud",
  "rev": 1,
  "saved_at": "2026-11-16T15:02:11+08:00",
  "status": "saved",
  "elapsed_s": 37.4,
  "images": [
    {
      "id": "img1",
      "name": "hud.png",
      "source": "C:/shots/hud.png",
      "size": [1280, 720],
      "refreshable": false,
      "items": [
        {
          "index": 1,
          "name": "shop",
          "type": "box",
          "box": [40, 520, 180, 80],
          "note": "",
          "template": "hud__img1__shop.png"
        }
      ]
    }
  ]
}
```

`box` is `[x, y, w, h]` = top-left corner plus size, in the 1280×720 original. The
template lives at `<data_dir>/templates/hud__img1__shop.png`.

## 4. Use it

Immediately — click the centre of the box:

```python
x, y, w, h = 40, 520, 180, 80
click(x + w // 2, y + h // 2)  # (130, 560)
```

Or ask for a ready-made module instead of hand-copying the numbers:

```
annotate_export(name="hud", fmt="py")
```

```python
"""Generated by image-annotate-mcp -- do not edit by hand."""

HUD_IMG1_SIZE = (1280, 720)

HUD_IMG1_SHOP = (40, 520, 180, 80)

TEMPLATES = {
    "shop": "hud__img1__shop.png",
}
```

## 5. If the user adds more

They keep the page open, draw three more boxes, and hit save again. You do **not** open a
new session — you wait on the same one, from where you left off:

```
annotate_wait(session="s1", since_rev=1, timeout_s=240)
```

`since_rev=1` means "wake me for the next save, not the one I already have". The new
payload contains **all four** items, not just the three new ones.

## 6. Close it

```
annotate_cancel(session="s1")
```

Leaving sessions open holds a port and a browser tab. The annotation is already on disk —
`annotate_load(name="hud")` gets it back later without any session at all.

## What it looks like when the user draws a polygon

```
annotate_wait(session="s1", since_rev=1)
```

```json
{
  "index": 2,
  "name": "skill_ring",
  "type": "polygon",
  "points": [[505, 175], [745, 340], [505, 505], [265, 340]],
  "bbox": [265, 175, 480, 330],
  "note": "",
  "template": "hud__img1__skill_ring.png"
}
```

`bbox` is the vertex bounding rectangle, usable anywhere a box is. The template is an RGBA
PNG masked to the diamond — outside the outline is transparent, so matching against it
ignores the corners of the bounding box.

## What it looks like when the user draws a point

```json
{
  "index": 3,
  "name": "start",
  "type": "point",
  "point": [640, 660],
  "note": ""
}
```

No `template` field. A point is for "click here", not for matching pixels — if you need a
template, ask for a small box instead.
